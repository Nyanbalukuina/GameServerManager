# 共通部分の仕様書

## 1. アプリの目的

GameServerManager（GSM）は、Windows上のゲーム専用サーバーをブラウザから構築・管理するアプリである。

ゲームごとの差異は専用機能として分離し、SteamCMD、事前検証、プロセス管理、Windows Firewall、CSRF保護、管理データ保存などを共通機能として提供する。現在の対象ゲームはARK: Survival AscendedとPalworldである。

## 2. 動作方針

- Windowsネイティブで動作する。
- 1タイトルにつき1サーバーを管理する。
- 構築前にOS、パス、空き容量、ポートを検証する。
- 長時間処理は進捗と失敗理由を画面へ表示する。
- デモモードではSteamCMD、実サーバー、Firewallを操作せず、Windows配布版では無効化する。
- LAN・VPN構成やルーターのポート転送はアプリの管理対象外とする。

## 4. アプリ構成

```text
React画面
  ↓ REST API
Spring Boot
  ├─ web            API・入力検証
  ├─ application    ユースケース
  ├─ domain         データモデル
  └─ infrastructure Windows・ファイル・外部プロセス
       ↓
SteamCMD / ゲームサーバー / Windows
```

フロントエンドからPowerShellやSteamCMDを直接実行せず、すべてバックエンドAPIを経由する。ゲーム固有処理はゲーム名フォルダーへ集約し、その配下をレイヤー別に整理する。

## 5. 必要な開発環境

- Windows
- JDK 21
- Node.js 24
- npm

Gradle本体のインストールは不要で、同梱のGradle Wrapperを使用する。

## 6. 初回環境構築

```powershell
cd frontend
npm.cmd install
```

バックエンド依存関係は、初回のGradle実行時に自動取得される。

## 7. 開発時の起動

ターミナル1でバックエンドを起動する。

```powershell
cd backend
$env:GAME_SERVER_MANAGER_ROOT = "$env:LOCALAPPDATA\GameServerManagerDev"
.\gradlew.bat bootRun
```

ターミナル2でフロントエンドを起動する。

```powershell
cd frontend
npm.cmd run dev
```

ブラウザで `http://localhost:5173` を開く。Viteは `/api` を `http://localhost:8080` へ転送する。

## 8. テストとビルド

```powershell
# バックエンドテスト
cd backend
.\gradlew.bat test

# フロントエンドテスト・検査
cd ..\frontend
npm.cmd test
npm.cmd run lint

# フロントエンドを含む実行可能JAR
cd ..\backend
.\gradlew.bat bootJar

# Javaランタイムを含むWindows配布物
.\gradlew.bat windowsDistribution
```

Windows配布物は `windows/publish/GameServerManager` に生成される。通常のテストは外部ネットワークや実ゲームサーバーへ接続しない。

## 9. 実行設定

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `GAME_SERVER_MANAGER_ROOT` | `%LOCALAPPDATA%\GameServerManager` | 管理データの保存先 |
| `GAME_SERVER_MANAGER_ADDRESS` | `127.0.0.1` | 管理画面の待受アドレス |
| `GAME_SERVER_MANAGER_PORT` | `8080` | 管理画面のポート |
| `GAME_SERVER_MANAGER_SECURE_COOKIE` | `false` | CookieのSecure属性 |
| `GAME_SERVER_MANAGER_DEMO_ENABLED` | `true` | 開発用デモ機能の有効化 |

LANやVPNから管理画面を利用する場合のみ、待受アドレスを明示的に `0.0.0.0` へ変更する。

## 10. 共通セキュリティ

- 初回起動時に単一の管理者を設定する。
- パスワードはbcryptハッシュで保存する。
- Cookieセッションを使用し、タイムアウトは30分とする。
- 状態変更APIをCSRFで保護する。
- CookieはHttpOnly、SameSite Strictとする。
- パスワードをログ、操作履歴、APIレスポンスへ出力しない。
- ゲームポートは指定された接続元だけに公開する。
- Firewall変更は専用の昇格タスクへ委譲し、GSM本体は制限付きユーザーで動作する。

## 11. 管理データ

管理データは `GAME_SERVER_MANAGER_ROOT` 配下へ保存する。

```text
config/     サーバー登録、自動運転設定
logs/       サーバーログ、操作履歴
backups/    設定・ワールドのバックアップ
tools/      SteamCMD
servers/    ゲームサーバー本体
```

OSのFirewall規則とタスクスケジューラは管理ルート外のWindows設定として扱う。
