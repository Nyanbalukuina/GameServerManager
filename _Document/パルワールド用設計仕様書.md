# パルワールド用設計仕様書

## 1. 文書の目的

GameServerManager（以下、GSM）でPalworld Dedicated Serverを構築・管理する機能の設計を定義する。本書はWindows上で直接実行する現行実装を基準とする。

## 2. 対象範囲

### 対象機能

- Windows上へのPalworld Dedicated Serverの新規構築
- SteamCMDの準備とサーバーインストール・更新
- 初期設定ファイルの生成・更新
- Windows Firewall受信規則の登録
- 起動、状態確認、安全停止、再起動
- 停止中のワールドZIPバックアップ
- 毎日の停止、バックアップ、起動による自動運転
- 操作履歴の記録
- 実サーバーを操作しないデモ構築・デモ管理
- GSM管理対象への登録

### 対象外

- 仮想マシン、WSL2、Dockerによる実行
- ルーターのポート転送、UPnP、CGNAT対策
- RCONおよびPalworld REST APIの外部公開
- 複数Palworldサーバーの同時管理
- 既存ワールド移行とプレイヤーID変換の自動化
- バックアップからの画面操作による復元

## 3. システム構成

```text
Reactフロントエンド
  └─ Palworld構築画面・管理画面
       ↓ REST API
Spring Bootバックエンド
  ├─ 入力検証・構築処理
  ├─ SteamCMD共通処理
  ├─ PalWorldSettings.ini処理
  ├─ Windows Firewall共通処理
  ├─ プロセス・Palworld REST API管理
  ├─ バックアップ・自動運転・操作履歴
  └─ サーバー登録情報の永続化
       ↓
Windows / SteamCMD / PalServer.exe
```

管理データの既定ルートは `%LOCALAPPDATA%\GameServerManager` とし、環境変数 `GAME_SERVER_MANAGER_ROOT` で変更できる。Webサーバーは既定で `127.0.0.1:8080` にバインドする。

## 4. サーバー識別情報

| 項目 | 値 |
|---|---|
| ゲーム識別子 | `PALWORLD` |
| サーバー識別子 | `palworld-main` |
| Steam App ID | `2394010` |
| ゲームポート既定値 | UDP `8211` |
| REST APIポート | TCP `8212`、localhost限定 |
| RCONポート画面既定値 | TCP `25575`、localhost限定 |
| 設定テンプレート | `DefaultPalWorldSettings.ini` |
| 設定ファイル | `Pal/Saved/Config/WindowsServer/PalWorldSettings.ini` |

現行仕様では1ゲームにつき1サーバーだけを登録できる。

## 5. 構築入力仕様

| 項目 | 必須 | 制約・既定値 |
|---|---:|---|
| サーバー名 | 必須 | 1～100文字、改行不可 |
| インストール先 | 必須 | GSM管理範囲内 |
| SteamCMD配置先 | 必須 | GSM管理範囲内 |
| ゲームポート | 必須 | 1～65535、既定値 `8211` |
| RCONポート | 必須 | 1～65535、ゲームポートと重複不可 |
| 最大プレイヤー数 | 必須 | 1～32 |
| サーバーパスワード | 任意 | 100文字以内 |
| 管理者パスワード | 必須 | 100文字以内 |
| 自動運転 | 任意 | 既定は無効 |
| 停止・起動時刻 | 自動運転時 | `HH:mm`形式、既定 `04:00` / `09:00` |
| 接続元範囲 | 必須 | LAN、Tailscale、カスタム、全許可の組み合わせ |

管理者パスワードなどの秘密値をログ、自動運転設定、操作履歴へ保存しない。

## 6. 構築処理

構築処理は同時実行を禁止し、次の順序で実行する。

1. 同一ゲームの登録有無、Windows環境、管理対象パス、空き容量、ポートを事前検証する。
2. `steamcmd.exe` がなければSteamCMDをダウンロードして安全に展開する。既存配置があれば再利用する。
3. SteamCMDでApp ID `2394010`をインストールまたは更新する。
4. `DefaultPalWorldSettings.ini`を基に `PalWorldSettings.ini`を生成・更新する。
5. 自動運転設定を保存する。
6. ゲーム用UDPポートのWindows Firewall受信規則を登録する。
7. Palworldプロセスを起動し、ゲームポートの待受を確認する。
8. GSMの管理対象へ `RUNNING` 状態で登録する。

Firewall登録後に起動または登録が失敗した場合、その構築で追加した規則を解除する。デモ構築ではSteamCMD、Firewall、実プロセスを操作しない。

## 7. 設定ファイル仕様

`PalWorldSettings.ini`の `OptionSettings` に次の値を作成または更新する。

| キー | 内容 |
|---|---|
| `ServerName` | サーバー名 |
| `ServerPlayerMaxNum` | 最大プレイヤー数 |
| `ServerPassword` | サーバーパスワード |
| `AdminPassword` | 管理者パスワード |
| `PublicPort` | ゲームポート |
| `RCONEnabled` | `True` |
| `RCONPort` | RCONポート |
| `RESTAPIEnabled` | `True` |
| `RESTAPIPort` | `8212` |
| `bIsUseBackupSaveData` | `True` |

文字列は引用符とバックスラッシュをエスケープし、改行を拒否する。既存設定の対象外キーは維持する。既存ファイルがある場合は `<管理ルート>/backups/palworld-main/config` に更新前バックアップを保存する。

## 8. ネットワーク・セキュリティ仕様

- Firewallで外部に許可するのはゲーム用UDPポートだけとする。
- 接続元はLAN、Tailscale、カスタムCIDR・IP、全許可から明示的に選択する。
- RCONポートとREST APIポートは外部公開せず、GSMからlocalhost経由で使用する。
- インターネットへ直接公開するためのルーター設定はGSMの責務外とする。
- 管理画面とWeb APIはlocalhostだけで公開し、更新系APIはCSRF保護の対象とする。ログイン認証は使用しない。

## 9. 管理操作仕様

| 操作 | 挙動 |
|---|---|
| 状態確認 | プロセスとゲームポートの状態を確認する |
| 起動 | 登録済み設定でプロセスを起動し、待受を確認する |
| 停止 | Palworld REST APIで保存後停止する |
| 再起動 | 保存・停止後に同じ設定で起動する |
| 更新 | 安全停止後、SteamCMD更新を実行して再起動する |
| バックアップ | 停止中のワールドをZIP化する |
| 操作履歴 | 操作種別、結果、日時、メッセージを追記する |

管理操作に必要な管理者パスワードは、操作直前に `PalWorldSettings.ini` から読み取る。

## 10. 自動運転仕様

- 毎日、設定した停止時刻に保存・停止する。
- 停止後にワールドのZIPバックアップを作成する。
- バックアップは3世代を保持する。
- 設定した起動時刻にサーバーを起動する。
- 自動運転設定は `<管理ルート>/config/palworld-main-automation.json` に保存する。
- 実行状態は `<管理ルート>/config/palworld-main-automation-runtime.json` に保存する。
- 自動運転設定に管理者パスワードを保存しない。

## 11. 主なAPI

| メソッド | パス | 用途 |
|---|---|---|
| POST | `/api/server-construction-plans` | 構築計画作成 |
| POST | `/api/server-construction-preflight` | 構築前検証 |
| POST | `/api/palworld/constructions` | 実サーバー一括構築 |
| POST | `/api/server-constructions/demo` | デモ構築 |
| GET | `/api/palworld/server/status` | 状態取得 |
| POST | `/api/palworld/server/start` | 起動 |
| POST | `/api/palworld/server/stop` | 安全停止 |
| POST | `/api/palworld/server/restart` | 再起動 |
| POST | `/api/palworld/server/update` | 更新 |
| GET | `/api/palworld/server/history` | 操作履歴取得 |
| GET / POST | `/api/palworld/automation` | 自動運転設定取得・保存 |

## 12. 完成条件

- GSM画面から事前検証、構築、起動、状態確認を一連で実行できる。
- Palworldクライアントから接続し、複数人でプレイできる。
- 保存・停止・再起動後も同じワールドを利用できる。
- 許可した接続元だけにゲーム用UDPポートを公開する。
- RCONとREST APIを外部公開しない。
- 手動更新、バックアップ、自動運転、操作履歴が機能する。
- 構築失敗時に不要なFirewall規則が残らない。
- バックエンドとフロントエンドの自動テストが成功する。
